Scenario

waitUntil — user-controlled gate

Listeners call event.waitUntil(promise) on a lifecycle event to hold progression to the next stage. The mock adapter already does this to gate ad-unit:render on its simulated auction. Below, a user listener adds a second waitUntil on ad-unit:fetch — both waiters must settle (Promise.all) before render fires.

Unit 1 — adapter only (baseline)

Only the mock adapter listens. ad-unit:fetch → waitUntil(auctionPromise) → resolves after 500ms → ad-unit:render.

Leaderboard · 728×90 · adapter-only Baseline idle

Unit 2 — adapter + user gate

A custom listener on ad-unit:fetch adds waitUntil(userGate). Render will not fire until both the adapter auction AND the user gate resolve. Use the buttons to resolve or reject the user gate; observe the stage-blocked / stage-unblocked and ad-unit:error events in the log.

What to watch in the log

ad-unit:stage-blocked fires when adUnit.blocked flips true. When all waitUntil promises settle, stage-unblocked fires and the next stage dispatches. A rejected waitUntil halts the lifecycle and fires ad-unit:error with the rejection reason.
